## 后续排查：列表页全部空白

### 现象
用户反馈登录后医院/医生/疾病/药品/药店/文章列表全部空白。

### 排查过程
1. curl 后端接口（不带 keyword）→ 全部正常返回数据，**数据本就在后端**，无需"搬数据"
2. mysql 客户端查 disease/drug/pharmacy/article 表 COUNT=0，但接口有数据 → 正在运行的后端(PID 3140, java.exe 占 8888)连的不是我 `mysql -uroot -p1234 localhost:3306` 连的那个库（存在多实例/多库情况，未深究，因为接口已能返回数据）
3. 关键对比：
   - `?page=1&size=50` → ✅ 返回 records 有数据
   - `?page=1&size=50&keyword=undefined` → ❌ 返回 `records:[]` 空数组

### 根因
小程序列表页普遍写 `keyword: keyword.value || undefined`，搜索框为空时值为 `undefined`。**uni.request 在 GET 模式下会把值为 `undefined` 的字段转成字符串 `"undefined"` 拼到 query string**（而非忽略），后端就拿 "undefined" 当真实关键词搜索 → 全空。各列表页 `catch {}` 又吞掉错误，所以用户只看到空白，没有报错提示。

### 修复
在 `src/utils/request.js` 的 `get` 方法里过滤掉 `undefined`/`null`/`''` 的参数，单点修复覆盖所有 GET 列表请求：
```js
get(url, data) {
  const params = {}
  if (data && typeof data === 'object') {
    for (const k in data) {
      const v = data[k]
      if (v !== undefined && v !== null && v !== '') params[k] = v
    }
  }
  return request({ url, method: 'GET', data: params })
}
```
POST/PUT 不过滤（body 可能有意传空）。重新 `npm run build:mp-weixin` 构建通过。

### 教训（通用）
- uni.request GET 模式下 `undefined` 参数 ≠ 被忽略，会被拼成字符串 `"undefined"`。小程序所有 GET 列表请求都应在发送前过滤 falsy 参数。
- 列表页 `catch {}` 空捕获会吞掉一切错误，调试期应至少 `console.error(e)` 或 toast，否则问题无从暴露。
- 后端多实例/多库时，`mysql` 客户端连的库与运行中 jar 实际连的库可能不一致，排查数据问题要以接口实际返回为准，不能只看 mysql 客户端查询结果。

## 第五轮：修复 dashboard 运行时报错

### 问题
微信开发者工具运行报 `TypeError: e.n is not a function`，页面白屏。

### 根因
dashboard.vue 在 `<template>` 里直接调用 `<script setup>` 中定义的函数：
```html
<view v-if="pendingPatients().length">
  <view v-for="p in pendingPatients()" :key="p.appointmentId">
```
uni-app 编译到微信小程序时，模板内调用 setup 函数会编译失败/运行时 `is not a function`。Vue3 Web 能跑但小程序不行。

### 修复
改为 `computed` 计算属性：
```js
import { ref, computed } from 'vue'
const pendingPatients = computed(() => (workbench.value?.todayPatients || []).filter(p => p.status !== 'COMPLETED'))
const completedPatients = computed(() => (workbench.value?.todayPatients || []).filter(p => p.status === 'COMPLETED'))
```
模板里去掉 `()`：`v-if="pendingPatients.length"` / `v-for="p in pendingPatients"`。

### 教训（通用）
- **uni-app 微信小程序模板内不能直接调用 `<script setup>` 的函数**（`fn()` 形式），必须用 `computed` 或 `method`。Vue3 Web 可以，小程序编译会报 `e.n is not a function`。
- **`<view :class="条件 ? 'a' : 'b'">` 三目动态 class 绑定在小程序运行时报 `e.n is not a function`**。编译产物中 `:class` 三目表达式会调用 `vendor.js` 的 `exports.n`（normalizeClass），该函数在该版本 uni-app 运行时存在引用问题。修复：改为 `v-if/v-else` 两个静态 class 的 view，或用 computed 拼接完整 class 字符串。对象语法 `:class="{active: bool}"` 不受影响。
- 全局扫描所有页面确认无其他 `v-if="fn()"` / `v-for="x in fn()"` / `{{ fn() }}` 模式。
